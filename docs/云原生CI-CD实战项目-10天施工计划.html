nmcli 配静态 IP sysctl 内核参数是干什么的 SELinux 三种状态

今天会踩的坑
  • 同步输入（WindTerm「发送到所有会话」）不能拿来操作 vim —— 2026-09-30 实测踩坑：在 A 上用同步输入 vim /etc/fstab 加注释，结果只有 A 改成功，B/C/D 纹丝未动。

swapon --show   # 应该什么都不输出
    只 swapoff 不注释 fstab，重启后 swap 回来，第 5 天 kubelet 直接启动失败，报错很难看懂。
  • SELinux 和 firewalld 实测都还开着：SELinux=Enforcing、firewalld=active。

    只 setenforce 0 不改配置文件，重启后回到 enforcing，各种权限诡异报错。
  • 内核参数还是默认值：实测 ip_forward=0、br_netfilter 未加载。 
    cat > /etc/modules-load.d/k8s.conf <<EOF
br_netfilter
EOF

net.bridge.bridge-nf-call-ip6tables = 1

EOF

lsmod | grep br_netfilter                      # 有输出才算成
sysctl -n net.bridge.bridge-nf-call-iptables   # 必须是 1，不能是报错
    为什么必须手动 modprobe（2026-09-30 踩过）：/etc/modules-load.d/*.conf 只在开机时由 systemd-modules-load 服务读取，对当前正在跑的系统完全无效。模块没加载时 /proc/sys/net/bridge/ 这个目录根本不存在，此时 sysctl --system 里的 bridge-nf-call 三条会静默失败（只打印一行 "cannot stat ..."，很容易被刷过去）。所以流程必须是：先 modprobe 加载模块 → 再 sysctl --system 应用参数。

② 备 manifest：改镜像地址

官方 manifest 把镜像写成 registry.k8s.io/...@sha256:xxxx。这里要改成和本地导入的镜像完全一致的名字，并且只留 tag、去掉 @sha256。两个原因：① 名字对不上，kubelet 找不到本地镜像；② 只要写了 @sha256，kubelet 就按那个具体摘要去找，本地导入的摘要和它对不上，就转去联网拉——又拉不到，于是 ImagePullBackOff。

    server_name todo.local;

        proxy_set_header Host $host;            # 关键！把 Host: todo.local 透传给 Ingress
        proxy_set_header X-Real-IP $remote_addr;
    }

概念拆解：请求是怎么一路走到应用的
  • 浏览器：todo.local 靠 Windows hosts 解析成 192.168.80.22（D 机）。
  • D 机外层 Nginx（:80）：小区大门。收到请求后按 proxy_pass 转发给集群入口——这就是 proxy_pass 的含义：反向代理的“交给谁”。
  • ingress-nginx（NodePort :31123）：单元门。按 Host: todo.local 匹配路由规则，决定去找哪个 Service。
  • app Service（:5000）：按标签选中后端 Pod，转发到 Todo 应用容器。
  • 一句话：proxy_pass = 集群外那一跳（Nginx → NodePort）；Ingress = 集群内的七层路由（按域名分流）。两者串起来，域名才真正“落到”应用上。

今天会踩的坑（本次实测，条条见血）
  • 镜像拉不动：registry.k8s.io 的真身 europe-west3-docker.pkg.dev（GAR）被墙，在线无解 → 走第①步的离线 tar（Windows 上 crane 从 k8s.m.daocloud.io 预拉）。
  • manifest 带了 @sha256 摘要：本地导入的镜像摘要（87a4f4f8…）和官方 pin（6ca5f62…）本来就不同，kubelet 会转去联网拉 → ImagePullBackOff。改镜像名时一并去掉摘要。
  • 用了裁剪版 / ACS 版 manifest 的 RBAC 缺权限：这类 manifest 常缺 coordination.k8s.io/leases、events、ingressclasses、namespaces，也没有 ns 级 Role/RoleBinding。后果是 controller 选不出 leader、不同步 Ingress，日志报 cannot get resource "leases"。修法：kubectl patch clusterrole ingress-nginx 补上这些规则。用官方完整版就天然没有这个问题。
  • 补完 RBAC 必须重启 controller：kubectl rollout restart deployment/ingress-nginx-controller -n ingress-nginx。informer 若在启动时因缺权限建立失败，不会自动重试，只会一直报 ingress does not contain a valid IngressClass。
  • admission Job 失败不会自动重跑：一次性 Job 打光 backoffLimit 就躺平。修法是先 kubectl delete job，再重新 apply。
  • admission Job 是“鸡生蛋”前置：controller 要挂载 create Job 生成的 secret 才能起，所以 Job 不通 → secret 不存在 → controller 永远 ContainerCreating（事件是 MountVolume.SetUp failed: secret not found）。
  • 本机通、跨节点不通：某台节点 kube-proxy 规则没同步（回滚遗留），表现为该节点的 NodePort 超时。重启该节点 kube-proxy 即可。
  • NodePort 端口每次重建都变：别把 31123 写死进 D 机 Nginx，每次都以 kubectl get svc 为准。
  • dnf install nginx 后服务不会自动启动：curl 返回 000（连接被拒＝没进程监听 80）。补 systemctl enable --now nginx。
  • 两层 Nginx 搞混 / 丢 Host 头：D 机 Nginx 少了 proxy_set_header Host $host;，Ingress 就匹配不到 todo.local，返回默认 404。

概念辨析（知其所以然）

  • 暴露端口 vs 反向代理 正交：docker -p / NodePort / 直接监听 只管"流量怎么进"；nginx / ingress 反向代理管"进来后怎么分发/改写/TLS 终结"。两者不是一回事。
  • 浏览器只碰 80：http://域名 默认 80，5000/3000 是 K8s 内部 Service/容器端口，被代理"翻译"掉了，跟浏览器无关。Service 端口 ≠ 容器端口（grafana Svc 80→容器 3000）。
  • .local 是装饰，Harbor 不是：grafana/todo/dashboard 的 .local 仅为人看 Web UI，纯 NodePort 直连 IP:端口 也行；Harbor 的 harbor.local 焊死在镜像 tag 与自签证书 SAN 里，改名代价大，保留。
  • 虚拟主机（你做过）vs TLS 终结（你没配）：D 机 Nginx server_name xxx.local = 基于域名的虚拟主机（单 :80 按 Host 头分流），你配过；TLS 终结 = 代理层持证书在 443 解密，你只"用过结果"（Harbor/Dashboard 的 HTTPS 是它们自己做的），Nginx 全站仍是 :80 HTTP 前端。

今天会踩的坑（全实测）
  • Grafana 密码不是 prom-operator：chart 随机生成，存 Secret，从 Secret 取；改密码后 Secret 旧值失效。
  • helm upgrade 报 repo not found：本地 tgz 安装不会写 repo 书签。继续用 helm upgrade monitoring /soft/kp.tgz，或先 helm repo add。
  • values YAML 缩进：service: 必须与 nodeSelector: 同缩进（2 格）挂在 grafana: 下，缩进错 helm 直接报错。
  • grafana Service 改端口必同步 Ingress：Svc 改 3000，Ingress 的 port.number 也要改 3000，否则 ingress 指向已消失的 80 → grafana.local 挂。
  • nodeSelector 对 prometheus/alertmanager 不生效：mon-values 里这两段路径少一层 prometheusSpec，helm 没注入；Operator 管理的 Pod 要用 kubectl patch prometheus/alertmanager ... CR。学习环境可暂不修（留 worker1 不影响功能）。
  • Dashboard raw 域被墙：用 git clone（github.com 主域）绕过 raw 子域 SNI 重置；不要 kubectl apply -f https://raw.githubusercontent.com/...。
  • etcd 修复会触发 apiserver 瞬时抖动：kubectl 短暂无响应，约 1 分钟自愈，别回滚。
